Clock local development

Prerequisites

  • Java 21 or newer and Maven 3.9 or newer
  • Node.js 26 and npm 11
  • curl and lsof for local scripts

Run the complete example

cd example-frontend npm ci cd .. ./start-dev-local.sh ./run-smoke-tests.sh ./stop-dev-local.sh

Logs are written to logs/. Project-owned PIDs are kept under .run/ and removed during a normal stop.

Test applications independently

mvn test cd example-frontend npm test npm run build npm audit --audit-level=critical

The smoke script validates health, REST JSON, frontend HTML, two real WebSocket messages, and the 750–1,500 millisecond cadence tolerance.

Demonstration constraint: this cadence verifies WebSocket server-push behavior; it is not a recommended production clock design. Real clocks should tick locally in JavaScript/TypeScript and synchronize with Java services only when needed.

Configuration

VariableDefaultUse
BACKEND_PORT8080Local backend and smoke target
FRONTEND_PORT4200Angular development server
FRONTEND_ORIGINhttp://localhost:4200Backend CORS/WebSocket origin
OPEN_BROWSER=falsetruePrint URLs instead of launching a browser

For deployed frontends, replace config.js with the public HTTPS and WSS backend URLs before Angular starts.

Troubleshooting

  • An occupied port is reported before either application starts.
  • A readiness timeout points to the corresponding file under logs/.
  • If a PID file is stale, run ./stop-dev-local.sh before restarting.
  • Production builds may need normal process permissions when a restricted sandbox terminates native build workers.
